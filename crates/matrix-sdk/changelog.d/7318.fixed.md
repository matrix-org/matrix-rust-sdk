When looking for the latest event using `Builder::new_remote`, we will try to back paginate in the store events too for 
up to 10 chunks.

This fixes an issue uncovered when shrinking the linked chunk for a room after it's been automatically back paginated, 
which in turn triggered a selection of new latest events for the room: however, since the code only supported searching 
for this latest event candidate in the in-memory events, and we just shrunk that, sometimes this just-selected event was
missing because it wasn't in this first chunk, which triggered another automatic back pagination attempt, in a loop of 
back pagination -> latest event selection -> back pagination, etc.
