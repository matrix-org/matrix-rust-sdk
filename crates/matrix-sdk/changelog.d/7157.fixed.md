[**breaking**] `QrAuthMessage::LoginProtocol` now carries a `LoginProtocolData`, so an
`m.login.protocol` message for an unsupported protocol is answered with an `unsupported_protocol`
failure instead of failing to deserialize. Over MSC4388 channels the device authorization grant
fields are now sent next to the `protocol` field, as in the latest MSC4108, and a device
authorization grant nested in a `device_authorization_grant` field is rejected as an unexpected
message. `QrAuthMessage::authorization_grant_login_protocol()` is no longer public.
