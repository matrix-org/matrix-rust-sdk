When either `RoomEventCacheState` or `ThreadEventCacheState` shrink their linked chunk to its first chunk, sometimes this operation can fail: we guard against this, so this is not problematic. However, when this happens and the metadata *can* be loaded, that metadata will be kept, and trying to use this cache will try using a newly created empty chunk with the stale metadata of a previously existing chunk that's no longer there, and that ends up causing the panic:

```
internal error: entered unreachable code: Inserting new chunk with no previous nor next chunk identifiers is impossible
```

The fix seems to be to just discard the stale metadata, which will be re-created for the empty linked chunk anyway.
