When a thread summary is recomputed (new reply, redaction, edit, or
redecryption), the root event's copy stored in the thread's own linked chunk is
now updated too, and the change is propagated to thread subscribers. Previously
only the room's copy of the root event was updated, so a thread-focused
timeline rendering the root event kept a stale thread summary (e.g. an outdated
replies count), and with a persistent event cache store the stale copy survived
restarts.
