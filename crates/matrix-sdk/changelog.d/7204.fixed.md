The `EventCache` receives its `RoomUpdates` directly from the sync response
flow, instead of via the `Client::subscribe_to_all_room_updates` channel.

Receiving `RoomUpdates` via `Client::subscribe_to_all_room_updates` poses
several problems. First off, this entire workflow is async, making things harder
to debug. Second, if the `EventCache` fails at some point, it will not make the
sync flow to fail. So in the case of Sliding Sync, the `pos` value is persisted
as if no problem happened. In this particular example, for the end-user, the
experience is terrible as messages can be missing! Now, if it fails, it makes
the entire sync response flow to fail.
