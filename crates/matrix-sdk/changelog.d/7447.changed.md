[**breaking**] With the `e2e-encryption` feature enabled, `Client::restore_session()`,
`MatrixAuth::restore_session()` and `OAuth::restore_session()` now fail with the new
`Error::MissingDeviceKeys` when the crypto store holds no Olm account for the restored session.
Previously the client silently created new device keys for a device that had already uploaded
its keys, and the homeserver rejected every key upload after that. To restore the same session
again, configure the persistent store it was created with. Clients that reuse an access token
without its device keys can opt out with the new
`EncryptionSettings::allow_restore_without_device_keys` field. `EncryptionSettings` struct
literals that list every field must add it.
