Register a sliding sync response's rooms with the latest-events machinery outside the `state_store_lock` region, instead of inside it. The latest-events computation task awaits `state_store_lock` itself, to persist a computed value, while holding locks of its own, so the two lock orders were inverted: a stall anywhere in the latest-events subsystem could wedge every sliding sync connection and every store-touching operation.

Relatedly, the latest-events computation task no longer holds the registered-rooms map lock while awaiting a per-room lock. The map lock is write-preferring, so a queued room registration parks every other reader in the subsystem behind it, while this task still holds its read guard and awaits the very room lock the compute task owns.
