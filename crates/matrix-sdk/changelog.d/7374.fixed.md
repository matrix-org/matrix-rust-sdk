When the `EventCache` fails to handle a room update (e.g. `JoinedRoomUpdate`),
it no longer ignores the error. Errors are forwarded to the caller. It will stop
the sync flow, and thus, in the case of Sliding Sync for example, will forbid
the `pos` value to be persisted.

This fix has raised another problem with the `NotificationClient`: `EventCache`
and `LatestEvents` were cloned from the original parent `Client`. This is no
longer the case: `NotificationClient` always has `EventCache` and `LatestEvents`
disabled.
