Only notify `Encryption::verification_state()` subscribers when the
verification state actually changes. Previously, every `/keys/query` response
for our own user re-published the current state, so a client that reacted to
updates by calling `Encryption::has_devices_to_verify_against()` or
`Recovery::is_last_device()` while our own identity was still unknown would
trigger a new `/keys/query` on each notification, looping indefinitely.
