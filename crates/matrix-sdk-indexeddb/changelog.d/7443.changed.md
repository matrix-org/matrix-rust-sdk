Events stored in the event cache now record their (possibly hashed) `state_key`,
if any, in a new `state_key` field. Empty state keys are stored too, so the
field is only missing for events that aren't state events. New
`events_state_key` and `events_state_key_timestamp` indexes allow efficiently
querying events by their `state_key`, optionally restricted to events older than
a given timestamp.

The database migration to version 11 empties the event cache, so it will be 
re-populated from the server.
