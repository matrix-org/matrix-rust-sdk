Events stored in the event cache are now indexed by their room, (possibly
hashed) `state_key`, if any, and timestamp in a new `events_state_key_timestamp`
index. Empty state keys are indexed too, so they can be told apart from events
that aren't state events. This allows efficiently querying events older than a
given timestamp while filtering on their `state_key`.

The database migration to version 11 empties the event cache, so it will be 
re-populated from the server.
