Dropping a SQLite store from a thread that isn't running within a Tokio runtime
(e.g. a foreign thread through the FFI bindings) doesn't panic anymore. The
store's connections are now dropped within the runtime that was used to open it.

Added a `SqliteConnections` wrapper (containing the old `SqliteConnections` struct, 
which is now `SqliteConnectionsInner`) that will ensure SQLite connections are
properly dropped in the correct runtime.
