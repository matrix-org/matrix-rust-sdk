Events stored in the event cache now record their (possibly hashed) `state_key`,
if any, in a new `state_key` column of the `events` table. Empty state keys are
stored too, so the column is only `NULL` for events that aren't state events.
New indexes on `(room_id, state_key)` and `(room_id, state_key, timestamp)`
allow efficiently querying events by their `state_key`, optionally restricted
to events older than a given timestamp.

The database migration adding this column empties the event cache, so it will 
be re-populated from the server.
